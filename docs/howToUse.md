# 개발과정 동기및 목적과 사용방법

[만들게된_이유]
시중에 나와있는 자녀 컴퓨터 제어앱은 한달에 10000원이 넘고 너무 비싸서 부모님의 돈을 지켜드리기 어려웠다.
그래서 "이거 내가 가지고 있는 지식이면 가능 하겠는데?" 해서 개발을 하게 되었다.

[네트워크기술스택]
1. Windows에 있는 프로그램을 종료시키고 프로세스 목록을 HTTP/HTTPS REST + 폴링 방식을 통해 전달한다
2. 서버역할. SSE (Server-Sent Events)를 사용하여  서버 → 브라우저 통신을 사용한다.
3. 브라우저 → 서버: Fetch API (REST)울 사용한다.
4. 서버 → DB: PostgreSQL 와이어 프로토콜을 사용한다.

[전체흐름]
[C++ 클라이언트] ──HTTP POST/GET (폴링)──▶ [FastAPI 서버 @ Vercel] ◀──SSE / fetch── [브라우저]
                                              │
                                              └──Postgres 프로토콜 (커넥션 풀)──▶ [Supabase DB]

[사용언어및_목적]
C++ = 클라이언트에서 Windows의 프로세스 데이터들을 수집하고 그 데이터들을 서버로 보내는 역할을 한다.
그리고 서버에서 받은 특정 프로세스 종료 명령을 집행한다.
Python = 중계. 즉 클라이언트에서 온 내용을 받고 DB와 연결하며 웹 브라우저에 표시한다.
그리고 브라우저에서 온 내용을 받는 역할도 한다.

[이루고싶은꿈]
이 캠프를 참여하여, 컴퓨터공학및 기타 기술능력과 AI활용능력을 쌓고, 무엇보다 여러 사람과 협력하는 능력이 부족해서
이 능력을 궁극적으로 기르기 위해서 이곳에 지원을 하게 되었습니다.

[문제_정의_및_해결력]
저는 시험기간에 이 생각을 하게되었습니다. 바로 "내가 이렇게 엄청 시험기간에 컴퓨터를 많이 쓰는데 나 자신으로는 제어가 힘드니까 외부에서 도와주는 힘이 필요하다" 라고 느끼게 되어 그때부터 생각을 하다가 시험이 끝나고 이 개발을 하게 되었습니다. 그리고 처음 개발을 했을때는 전부터 있었던 개발 악습관인 "큰 프로젝트가 좋다." 라는 악습관에 매몰되어 한동안 진척이 없다가 나 자신에게 이렇게 물었습니다. "그냥 작게작게 해보자!" 이 생각으로 저는 하나하나씩 작게 즉 "프로세스 목록 탐색" -> "프로세스 목록을 std::vector에 담기" -> "네트워크로 보내기" 이런식으로 생각을 해서 결국 MVP 최소 구현을 만드는데 성공을 하였고 이로 인하여, 저의 코딩자존감의 발판을 마련하는데 매우 큰 기여를 하였습니다.

[소통협력]
처음에 개발을 했을때는 저 혼자 개발을 하였으나, 코딩학원에서 선생님과 의견을 나누고 그중에서 가장 인상깊었던것은. "컴퓨터 프로세스 목록중에 어플만 가져오고 백그라운드 프로세스는 가져오지 말자." 는 말로 협력의 맛을 느껴서 이곳 카카오AI루키에 지원을 하게 된다면 얼마나 더 많은 협력에 맛을 느낄지 너무 기대되어서 이곳에 지원하게 되었습니다.

[프로그래밍_경험역량]
그전까지만 해도 저는 바이브코딩에 약간 부정적인 인식을 가지고 있다가. 이 프로젝트에서 Claude Code Opus 5.5를 사용했다가 생각보다 너무 잘만들어서, "바이브코딩도 충분한 설계와 코딩지식이 베이스가 있으면 잘되구나!" 생각을 하여 저의 느린개발속도를 강하게 극복을 해주는 발판이 되었습니다.
